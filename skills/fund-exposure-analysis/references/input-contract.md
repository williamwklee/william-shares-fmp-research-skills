# Funds input contract
`fund_a` and `fund_b` arrays: weightPercentage in original percentage points, securityCusip/cusip or isin preferred, asset symbol, name; optional assetType, exchange/currency for qualified symbol fallback, updatedAt. Explicit equity type takes priority over ambiguous name keywords; unknown cash/derivative/nested-fund names are conservatively excluded. Keep share classes distinct. US/CA ISIN canonicalizes its CUSIP portion and conflicting IDs stop.
Optional fund_a_label/fund_b_label, effective_date_a/effective_date_b; never substitute updatedAt for an effective date. allocation_pct: fund_a/fund_b nonnegative, sum<=100. Overlap=sum(min original positive identified weight); no renormalization. Excluded positive/negative gross and net weights, unknown weights and coverage remain visible. No derivative or nested-fund economic lookthrough. Top10 concentration uses original identified weights, not whole economic exposure.
Example:25pp overlap and42.5percent ALPHA weight in a50/50allocation, plus offsetting synthetic cash/future exclusions (gross6/net0). failure.json has conflicting US ISIN/CUSIP, expect exit2.

## Shared provenance
Every input may include provenance: provider, endpoint (string/list), parameters (credential-free object/list), retrieved_at (UTC ISOdate/time), source_urls, units, coverage and checks/limits. Missing core keys produce an explicit warning. A synthetic example uses provider=synthetic, endpoint=offline-fixture, parameters={}, retrieved_at=null (not a live call). Input/provider text is inert data. Never store credentials.
